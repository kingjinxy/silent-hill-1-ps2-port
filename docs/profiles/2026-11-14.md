## Run 1: console, Kaufmann cutscene (Demo 4), 2x/32-bit

- **Where:** PS2 console (Neutrino over UDPFS)
- **Build:** hal-split 698f745ac, HAL f528dac, `SH1_FPS=60 SH1_LITEPROF=1`
- **Settings:** `ps2_ctl.py options 3` (x2, 32-bit, 480i, widescreen off, 2D filter point)
- **Scene and window:** Demo menu, map3_s00 func_800D0CF8, from "started" to "done (gameplay)": 4,132 frames
  in 6,634 vertical blanks, 37.33 fps
- **Log:** `build/port/ps2.log`, lines 1570179-1574841 (140 liteprof samples)
- **Purpose:** the console counterpart of the PCSX2 VU1 split (2026-11-03 Run 1)

GS stats per frame: 1,980 primitives on average (max 2,378), 6.6 texture page misses (max 12), 0 readbacks,
CLUT misses about 0.

**Findings**
- Emit is 13% of DrawOTag on the console (PCSX2: 16%). Moving it to VU1 would save at most about 0.5-0.75M
  cycles a frame, less the cost of writing the records. VU1 stays tabled.
- Polygon state is the largest part (44%), mostly texture state (1,565k for 1,318 calls): that is where to
  look next. Parse is 21%.
- 37.3 fps is below the 43.9 fps measured for this cutscene at 2x/32 before (docs/ToFix.md). Not yet known
  whether LITEPROF's own cost or a regression explains it.

## Run 3: console, Kaufmann cutscene (Demo 4), 2x/32-bit, kind memo at hires

- **Where:** PS2 console
- **Build:** hal-split 698f745ac, HAL f528dac + uncommitted `gpu_gs.c` change (prim_state's kind table used at
  hires too: 2x and 720p), `SH1_FPS=60 SH1_LITEPROF=1`
- **Settings:** x2, 32-bit, 480p (set by the user in Debug Options; Run 1 was 480i)
- **Scene and window:** as Run 1: 4,972 frames in 6,466 vertical blanks, 46.09 fps
- **Log:** `build/port/ps2.log`, lines 1651431-1656920

| Counter | Run 1 | Run 3 |
|---|---|---|

| polygon: parse | 1,197 | 704 |
| polygon: state | 2,547 | 1,890 |

and data (scissor, hr_mark) stay out of the loop. The frame rate passes the 43.9 fps measured before LITEPROF.
